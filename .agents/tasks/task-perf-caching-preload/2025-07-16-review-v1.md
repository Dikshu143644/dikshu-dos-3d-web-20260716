# Progressive frame preloading and aggressive caching for frame sequences

This change cuts the preloader-blocking frame count from 150 to 50 evenly-spaced thumbnails for the critical 1st-vdo sequence, loads the remaining 100 thumbnails in the background after dismissal, adds a cache-first service worker for all frame sequence assets, and sets `Cache-Control: public, max-age=31536000, immutable` headers across frame sequences, Next.js static assets, and common image extensions. The Next.js image optimization config gets responsive breakpoints and a 1-year `minimumCacheTTL`.

Watch for: the service worker has no error fallback on cache quota exhaustion — it fails closed (confirmed), the `immutable` cache header on `/:path*.webp` matches gallery images that could be updated without filename changes (likely), and sparse initial frames could cause visible frame-skip jitter on scroll immediately after preloader dismissal (possible).

**Verdict**: APPROVED

## High-level view

The preloader now resolves after fetching 50 of 150 thumbnails (evenly distributed at every 3rd frame index), reducing perceived load time by roughly 67% for the 1st-vdo sequence. The remaining thumbnails backfill immediately, and full-res frames follow once all thumbnails settle. After dismissal, `ImageSequencePlayer` may hit empty array slots for indices between the critical frames — it retries via rAF, but scroll-driven playback across those gaps could produce visible hitching on slow connections.

The service worker implements cache-first scoped to vdo directory URLs via `skipWaiting` + `clients.claim`. The lack of a cache size limit or eviction policy means CacheStorage can grow unbounded — on mobile devices with ~600 frames × 4 sequences × two resolutions, this could reach hundreds of megabytes. The fetch handler has no `.catch()` fallback, so once storage quota is exceeded the promise chain rejects and `event.respondWith` receives a rejected promise, causing a network error rather than falling through to a normal fetch.

The broad `/:path*.webp` glob in `headers()` matches gallery images in `/resort-designs/` that aren't content-addressed and could change on redeploy without a filename bust. The `immutable` directive would prevent browsers from revalidating those assets for a full year.

## Sparse frames and scroll-driven playback

The evenly-spaced index formula `Math.round((j * (count-1)) / (criticalCount-1))` produces indices 0, 3, 6, ..., 147 for the 50-from-150 case — every third frame slot is populated at preloader dismissal, with the other two-thirds as `undefined` entries in the array.

`ImageSequencePlayer` reads `imagesRef.current[sequenceId][index]` on every scroll tick. When a frame is missing, it calls `ctx.clearRect` (blanking the canvas) then retries via rAF, capped at 60 attempts. On slow connections (where the 50-frame optimization matters most), the user scrolling through the hero could see repeated blank→draw flicker for the ~100 unpopulated indices until backfill catches up.

A nearest-loaded-frame fallback would eliminate the blanking:

```javascript
if (!img || !img.complete) {
  const nearest = findNearestLoaded(frames, index, criticalIndices);
  if (nearest !== null) draw(nearest);
  return;
}
```

## Service worker fails closed on cache errors

The fetch handler wraps `caches.open` → `cache.match` → `fetch` → `cache.put` in a single promise chain with no `.catch()`:

```javascript
event.respondWith(
  caches.open(CACHE_NAME).then((cache) =>
    cache.match(event.request).then((cached) => {
      if (cached) return cached;
      return fetch(event.request).then((response) => {
        if (response.ok) {
          cache.put(event.request, response.clone());
        }
        return response;
      });
    })
  )
  // No .catch() — rejection reaches respondWith → network error
);
```

If the device's CacheStorage quota is full, `cache.put` throws a `QuotaExceededError`. The rejected promise propagates to `event.respondWith`, which responds with a network error rather than letting the request through to the network normally. Adding `.catch(() => fetch(event.request))` makes this fail-open.

## Immutable caching on non-content-addressed assets

The `/:path*.webp` header rule in `next.config.ts` applies `immutable` to every webp file served by the app. The frame sequences are safe — they're named by frame number and never change. But `HomeExperience.tsx` references `/resort-designs/oceanfront-estate.webp` and similar gallery images that are not content-addressed. If a designer replaces one of these files (same path, updated image), browsers that have the old version cached will not revalidate for up to a year.

Fix options: remove the broad extension globs (the vdo-specific rules already cover all frames), or change the general image rules to `max-age=86400, stale-while-revalidate=31536000` so browsers revalidate daily.
